# Setup Checkpoints

Use this checklist to avoid skipping hidden setup work.

| Phase | Check |
| --- | --- |
| Archive | File list inspected before extraction |
| Mode | Human chose repository, project folder, personal file steward, or reference-only |
| Consent | Human understands no file/folder creation, scaffolding, moves, deletes, uploads, overwrites, sharing, installs, replacements, or schedule changes happen without approval |
| Checklist | Baseline modules identified; optional modules marked active, inactive, or not-applicable |
| Tools | Needed tools checked for chosen mode |
| Skill | Harness skill installed or available from extracted package |
| Repo access | Repository exists locally, or clone/access path is known, if repository mode |
| Repo facts | Project name, repo slug, CLI name, default branch, tracker known, if repository mode |
| Personal scope | Install folder, managed folders, off-limits folders, and scan depth known, if personal mode |
| Authority model | Repository-visible docs and role-restricted external docs separated |
| Connections | Permanent external systems named with credential storage and revocation paths, if needed |
| Scaffold | `AGENTS.md`, `AGENTS-TOC.md`, protocols, and CLI created or audited |
| CLI | help, context, protocols or inventory, and preflight run |
| Tests | CLI tests run or test gap reported |
| Handoff | Local harness docs become authority |
| First action | One useful next action proposed |

Optional modules:

- secrets posture
- tracker wrapper
- CI/path registry
- external MCP/workspace boundary
- permanent Drive/email/document/database connection registry
- advanced hooks
- evidence map
- personal folder inventory
- cleanup plan receipts and undo
- agent-client heartbeat, loop, goal, scheduled check-in, or noninteractive run
